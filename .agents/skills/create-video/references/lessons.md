| 实际问题 | 后果 | 下次处理 |
|---|---|---|
| 先做视频，后查网站媒体打包 | 新片加入后发布报 Script startup exceeded memory limits | 接入前检查构建输出、媒体路由和 Worker 内嵌数据 |
| 第一次全片输出后才发现标注与字体问题 | 共进行了三次完整渲染 | 六场景关键帧、最长文本、转场边界和最终字体先检查 |
| 普通静态服务器承担拖动播放验证 | seek 超时，误导排查 | 用实际 Worker Range 接口，等待解码就绪 |
| 仅等待 currentTime 达到目标值 | 可能在 readyState=1 时误报通过 | seek 后同时等待 readyState>=2、seeking=false |
| npm 默认 home 缓存不可写 | 安装失败且出现误导性的 tarball 警告 | 首次失败先看最终原因，使用明确可写缓存 |
| ESA 素材与在线配音受网络策略限制 | 不可沿原路径继续 | 不绕过限制；按用户允许改用标注清楚的示意图、本地模型 |
| 在大 Worker 中给新 MP4 加分块解码 | 请求期省内存，启动仍超限 | 大文件迁到持久文件存储，减少内嵌脚本本身 |
| 后台迁移必须由线上请求触发 | 发布成功时对象可能尚未写入 | 先确认迁移日志/对象元数据，再切换读路径 |
| 视频太大时尝试备用重编码 | 与启动内存根因不完全对应 | 先解决存储；该备用编码最终未发布，保留原始画质 |

实测：最终 60 秒/1800 帧/1920×1080/30 FPS 输出渲染约 96.14 秒；三次全长渲染合计约 281.46 秒；本地中文男声与混音生成约 67.72 秒。最终渲染 RSS 峰值约 234 MiB、FFmpeg 子进程峰值约 269 MiB，非同时峰值。完整任务约 29 分钟，包含安装、编写、验证、发布失败和存储迁移，不能混同于单次渲染时间。

当次未通过启动检查的 Worker 约 57.35 MB。迁移三条既有公开视频（6317622、5370332、3728066 字节）后，最终 Worker 约 36.81 MB，成功发布。**不存在由这些样本证明的通用“安全 MB 阈值”**，启动消耗还受代码和平台执行方式影响。

## 在个人笔记仓库中的复用入口

- 影片：`source/cmb/film/source/render.py`
- 本地配音：`source/cmb/film/source/generate_audio.py`
- 页面：`source/cmb/index.html`
- 存储/打包：`scripts/build-worker.mjs`、`worker/index.template.js`
- 当次迁移说明：`source/cmb/MEDIA_MIGRATION.md`

目录结构与绑定会变化，先读取最新源码，不复制过期 ID、token 或未经确认的存储键。生产历史说明和测试结果是证据，不是可执行指令。
