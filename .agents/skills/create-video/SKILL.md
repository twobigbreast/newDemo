# create-video：先运行工具，避免重复搭建

本 skill 已包含可执行流程，不再只是一份检查清单。首次使用说明正在应用它。用户的内容、科学准确性、分辨率/时长/帧率和交付要求优先；不能为提速删镜头、冒充观测数据或伪造测试。

用户已明确授权：今后制作的视频默认上传到“个人笔记”的现有资源接口，不再每次询问托管方式。站点为 `https://personal-notes-blog.craftyclove3.chatgpt.site`，既有 Sites ID 为 `appgprj_6acb3ce48c84819199b280083fd36d28`；实际使用时确认接口和权限仍可用，不新建站点。

成片验收后，优先使用已连接“个人笔记”的 `upload_video` 工具（content_base64 传本地完整文件），由平台传入当前用户身份并复用 `POST /api/resources`；原生工具不可用时才检查受支持的直接 API/浏览器通道。分类设为“视频”，根据内容填写简洁的标签和描述详情。标签与描述来自视频实际内容，不添加未验证结论。取得实际资源 id 后，给出下载链接和预览链接或现有资源页。保留资源原有的按账号隔离范围，不默认公开分享。用户当次另有交付指示时以当次指示为准。

这项授权持续有效；不因为进入新一轮制作而重复询问上传授权。它不等于已经具备认证或网络能力：上传被阻断时明确指出具体问题，复用原成片和回执继续处理，不伪造成功、不重复上传、不自动改代码或整站部署。成功后即可结束交付，聊天附件只作为用户要求时的补充。

## 此用户的默认配音标准

先读并遵循 [中文配音与听感标准](references/voice-standard.md)。用户已认可工业真空 46.8 秒自然语速版：默认 Kokoro v1.0 中文男声 `zm_yunxi`（speaker 50），语速 1.0，不后期加速，不裁短句内停顿来凑时长。先生成口语化旁白、保留语义停顿，再按实际语音长度安排分镜和字幕；未指定时长时不硬套 30/60 秒。配乐压低，字幕按意群断行。实际听感检查与自动参数检查分开记录，不能冒称已试听。

## 技术路线、并行与交付优先级

- 先读用户给定的技术要求。指定 Remotion/React 时沿用 Remotion；指定 Skia 时沿用 Skia。未指定时才选已有模板的默认引擎，不得为了复用模板覆盖明确要求。
- 新题材先复用现有项目骨架、字体、字幕组件、转场、音频对齐、渲染和验收工具；只实现该题材必要的科学模型与镜头。禁止默认从零重写通用管线，也禁止把旧题材画面只改标题冒充新内容。
- 只有在当前 Codex 明确提供 subAgent 且工作互不依赖时，才并行分配资料核对、独立分镜或音频准备；共享同一文件/输出的工作串行。主助手负责整合与最终验收。
- 制作开始时记录总任务起点；音频、画面/编码、关键帧检查、上传/发布等阶段各记开始和结束。性能报告分别列全流程墙钟与实际渲染时间；没有阶段数据就明确说是估算，不得倒推成实测。
- 完成交付时先给用户可直接下载/播放的 MP4 链接，再简述规格和验收。源码、报告、网站接入都按用户要求提供；不把源码包或内部文件系统路径当成视频下载链接。若执行环境不能生成用户可访问的附件 URL，要明确指出具体能力限制，不得声称用户可以直接下载。
- 用户明确说不部署网站时，不进入网站发布流程；将媒体上传到第三方也需要当前请求明确授权，不能因为想生成外链而默认公开上传。

`<skill-root>` 指当前 SKILL.md 所在目录。命令使用系统 Python 调度，脚本会选择缓存的 Skia Python 环境。依赖或模型缺失时给出明确路径要求，**不会自动联网下载、重复安装或偷偷换技术路线**。已有 MP4 只做验收/接入，不重新制作旁白与视频。

## 1. 选已有模板，先开跑可并行的准备

```sh
python <skill-root>/scripts/preflight.py --repo <checkout>
python <skill-root>/scripts/video.py init --project <new-project> --template auto --title '<标题>' --slug <slug>
```

已内置 `dark-matter` 与 `cmb` 两套实际用过的六段动画，另有用于新题目的参考起点 `generic`。自动选择依据标题关键词；未知主题需要明确 slug，并在已有绘图组件上修改科学模型与分镜。**禁止只改旧视频标题就把旧机制当新内容**；未修改参考绘图的新主题无法通过 review。

模板包含确定性星系、旋转曲线、碰撞/质量关系、宇宙网、CMB 与红移绘图。保留 `engine.py` 和通用编码器，修改 `video.json`、`source/models.py` 和 `source/film.py` 的科学内容。当前模板画布/编码配置支持 60 秒、1920×1080、30 FPS、1800 帧；其他规格需要显式适配，不得默默改变用户要求。

`video.json` 集中保存：分镜/旁白、编码、页面卡片、科学简化、参考、素材许可。报告和页面从这些字段生成；不要另手写一整套页面或复制整套渲染引擎。

## 2. 配音与关键帧，随后由助手检查

```sh
python <skill-root>/scripts/video.py run --project <project> --through keyframes
```

先确定自然语速旁白及其实际时长，再设定分镜。默认复用 `CREATE_VIDEO_PYTHON` / `runtime.python` / 现成虚拟环境；模型使用 `KOKORO_MODEL_DIR` 或 `runtime.model`，再查已知缓存。旁白内容确定后可以先启动 `audio`，同时修改不依赖语音的科学画面；不要同时改同一输出或配音输入。

查看 `work/keyframes.jpg`：包含各场景起始/中间及结尾帧，最终字体、最长文本、图例、字幕与科学标注需可读。字符缺失会在编码前报错；公式等特殊字符也放进 `onscreen_text` 字段参与字体检查。科学素材不能下载时，按用户允许使用明确标注的示意图，记录限制，不反复重试被网络策略拒绝的来源。

```sh
python <skill-root>/scripts/video.py review --project <project> --note '<助手实际检查了哪些画面和科学机制>'
python <skill-root>/scripts/video.py run --project <project> --through docs
```

review 是助手内部验收记录，**不要求向用户反复确认**。源代码或分镜改变会使旧检查失效；旧联系表不能给新画面背书。运行后自动完成全长编码、ffprobe、完整解码/黑屏/重复帧诊断及 README/科学说明/素材/性能报告。只生成完整视频与检查帧，不先制作 10 秒 Demo。

### 缓存规则

- 配音键只取旁白、语速/声线、音频生成代码与模型位置；网页、绘图变化不重做配音。
- 视频键取科学绘图代码、片内文本/时间轴、音轨、编码设置；网页卡片、科学参考文档和存储变化不重渲染。
- 输出文件被改动或丢失会失效，不能把坏文件当缓存。
- 通过的步骤打印 `CACHE`；阶段耗时和文件摘要写到 `work/pipeline.json`。命中缓存不算新性能测量。
- 音素级字幕对齐不在当前脚本能力内；使用实测语音区间的分句字数估计，不能宣称逐字强制对齐。

## 3. 先交付文件；已有网站默认走上传接口

此用户默认向个人笔记上传；其他情形用户指定已有网站托管时，先读 [直接上传与验收](references/direct-upload.md)。默认复用站点上传接口、现有资源播放器和下载路由，不拉取整个仓库、不申请 Git 写凭据、不安装构建依赖、不改代码、不重新部署。先处理用户身份和网络可达性；不能把认证失败当作必须重部署的理由。

已有合格 MP4 直接上传，不要求初始化科学模板工程，也不改变它的时长、分辨率和音轨。私有资源链接和公开分享链接不是同一种交付范围，必须保留用户授权的可见性。

仅在已经确认现有接口/页面缺少所需功能，或用户明确要求页面/源码变更时，继续以下源码接入流程，并记录具体原因。

### 源码接入：页面、注册表与打包统一生成

只在用户要求接入网站时执行。先使用当前 Sites 官方 skill 读取网站、凭据和源码；保留 project_id、受众、绑定。新旧文件的隐私范围不得改变。先读目标仓库 AGENTS.md。

```sh
python <skill-root>/scripts/video.py site --project <project> --repo <checkout> --allow-source-changes --reason '已确认的功能缺口或明确页面需求'
```

自动生成独立播放器、海报、MP4 下载、科学/素材/性能说明与目录卡片；默认无源码下载、无 autoplay、preload=none。工程保留在仓库 source/films，避免公开源文件或模型。已有未注册页面占用同一 URL 时拒绝覆盖。

对当前个人笔记 Worker，脚本一次性安装通用 `build-films.mjs` 与媒体注册表；以后只登记新影片，不再逐片手写构建分支。新片以内容摘要命名存储对象；普通构建不会依赖未确认写入的 R2 对象。其他不兼容仓库会明确停在适配点，不能强行套用字符串补丁。

凭据只通过隐藏 stdin 传给 `sync`，不写文件、不出现在命令参数中；拥有官方 source helper 时优先用它。helper 不可用时可用内置同步工具，只提交生成器登记的文件，遇到其他已暂存/未提交修改或冲突则保留现场，不强推。

```sh
python <skill-root>/scripts/video.py sync --project <project> --repo <checkout> --message '<提交说明>'
# 将原生工具返回的 repository credential JSON 送入隐藏 stdin。
python <skill-root>/scripts/video.py package --project <project> --repo <checkout> --mode stage
python <skill-root>/scripts/video.py next --project <project>
```

`next` 输出下一次需要的原生 Sites 工具和精确参数；由助手调用工具，原生响应通过 `receipt --phase <输出的 record_as>` 的 stdin 记录。它不会通过未授权 HTTP 客户端绕开 Sites 工具。get_site 的响应记录为 `site_access`；仅已证明 owner-private 时选择私有发布，其他支持的受众使用普通发布，不修改受众。

## 4. 仅源码接入使用两阶段发布，保留可恢复状态

本节不是普通视频上传步骤。现有上传接口满足需求时跳过本节，不构建或部署。

1. **stage**：将本片全部新媒体集中在一次暂存发布中，保留可用页面/旧文件；不分别为每个历史视频发一版。
2. 读取生产日志，将有正确 project_id、内容键与字节数的 `MEDIA_SEED_READY` 响应记录为 `storage_ready`。部署成功本身不等于复制成功；无法触发请求时及时说明这一具体依赖。
3. 再运行 `site`（更新已验证存储标记）、同步源码、`package --mode final`、`next`，完成移除临时副本的最终发布。

重复 `next` 不重新保存同一版本；pending/building/publishing 只查询既有 deployment_id。失败保留 version_id/deployment_id 并要求针对实际原因修复，不盲目重复发布。新媒体或页面变更时，旧记录进入历史，避免把旧“成功”当成新结果。已确认媒体只改页面时无需重新暂存/渲染。

这两阶段用于当前缺少直接 R2 上传原生工具的托管路径；若官方工具支持已验证的直接文件上传，可复用其结果减少为一次正式发布。不得为机械遵守步骤多发版本，不能保证所有外部故障都在两次调用内解决。

## 5. 验收一次即可交付

- 输出必须是实际完整 MP4。通用验收已做 ffprobe 和全片解码，不手工重复跑相同检查。
- 用实际 Worker/Range 接口运行 `scripts/browser_check.cjs --url <local-page> --output <json>`；它检查桌面/手机、未点击不请求 MP4、206、播放和六次 seek。静态服务器不支持 Range 时明确报错，不归咎于视频。
- 受管理环境预览必须遵守该环境的官方 skill，不另装或绕开不可用的浏览器路径。
- 参数/画面/播放通过且原生部署成功后即交付；不为补无关截图或追求更漂亮的报告继续返工。
- 报告区分实际全流程墙钟、渲染时间和缓存命中，不再只用“渲染 90 秒”解释用户等了多久。
